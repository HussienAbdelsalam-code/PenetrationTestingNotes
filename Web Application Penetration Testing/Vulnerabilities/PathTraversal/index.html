    Path Traversal Vulnerability

    What

    • Path traversal vulnerabilities enable an attacker to read arbitrary files on the server that is running an application.
    • The attacker can read sensitive files including:
      • Application code and data.
      • Credentials for back-end systems.
      • Sensitive operating system files.

    Where to look:

    1. Pages/Endpoints.
    2. Parameters.
    3. File upload points.
    4. Headers.
    5. Filenames.
    6. API paths.

    Data Flow

    Basic Payloads

    • Linux test payload: ../../../etc/passwd
    • Windows test payload: ..\..\..\windows\win.ini

    Bypassing Defenses

    • You might be able to use an absolute path from the filesystem root such as ?filename=/etc/passwd without using any traversal sequence as in TestCase#2.
    • You might be able to use nested traversal sequences, such as ....// or ....\/, these revert to simple traversal squences when the inner sequence is stripped as in TestCase#3.
    • You can sometimes bypass the sanitization of filename parameter of a multipart/form-data by URL encoding, or even double encoding, the ../ characters as in TestCase#4.
    • You might include the required based folder followed by suitable traversal sequence, such as filename=/var/www/images/../../../../etc/passwd as in TestCase#5.
    • You might use a null byte to effectively terminate the file path before the required extension, the null byte %00 as in TestCase#6.

    Test Cases:

    Test Case 1:

    • The web app loads an image /image?filename=45.jpg
    • Test payload: ../../../etc/passwd

    Test Case 2:

    • The web page loads an image from /image?filename=45.jpg.
    • Test payload: filename=/etc/passwd

    Test Case 3:

    • The web page loads an image from \image?filename=15.jpg
    • Test payload: filename=....//....//....//etc/passwd

    Test Case 4:

    • The web page loads an image from /image?filename=15.jpg
    • We send the request to Burp intruder and used fuzzing path traversal.

    Test Case 5:

    • The web app loads an image from filename=var/www/images/15.jpg.
    • From the parameter value format we knew that it needs the base folder to work, so our test payload was filename=var/www/images/../../../etc/passwd

    Test Case 6:

    • The web app loads an image from filename=15.jpg
    • The payload we uset to omit the file extension using null byte: filename=../../../etc/passwd%00.jps

    How To Prevent

    • The most effective way to prevent path traversal vulnerabilities is to avoid passing user-supplied input to filesystem APIs altogether.
    • If you can't avoid passing user-supplied input to filesystem APIs, we recommend using two layers of defense to prevent attacks:
      • Validate the user input before processing it. Ideally, compare the user input with a whitelist of permitted values. If that isn't possible, verify that the input contains only permitted content, such as alphanumeric characters only.
      • After validating the supplied input, append the input to the base directory and use a platform filesystem API to canonicalize the path. Verify that the canonicalized path starts with the expected base directory.
